# 2026年11月17日补充实验

本目录实现优化讨论中的M3计数内核，并在指定SSH服务器上单进程串行执行。协议见supplement_v3/PROTOCOL.md，旧版与修订版数据保持原样。

M3沿用M2的几何分类器。安全细格直接累加格内点数，风险点仍逐点调用直接粗编码。它省去逐点标签及内部标记输出列表，但仍扫描输入，不能声称整体复杂度由O(N)降为O(U)，也不消除原分类器的数值局限。

## 冻结范围

21条成本序列、9条漂移序列、108组新区域检查、12条旧失败坐标与分辨率组合的回归检查，以及独立Python内存测量。直接基线同时包含列表计数B1与流式计数B1s。每个随机种子取3次重复的累计耗时中位数，然后报告3个种子的均值及范围。重复计时不是独立地理样本。

## 执行与复现

先按根目录requirements.txt建立Python3.12独立环境。原服务器使用已存在的h3-boundary-aggregation-study/venv，不重新安装或修改依赖。

```bash
python test_count_recoder.py
python -u run_supplement_v3.py > supplement_v3/run.log 2>&1
```

第一次运行从空结果目录开始。相同冻结源码可跳过已完成的成本与漂移任务；源码哈希改变时拒绝续跑。更改实现应创建新目录和新的登记，不能覆盖已有计时。计时任务不要并行运行。

结果写入supplement_v3，环境与源文件SHA256保存在environment.json。完成文件仅表示登记任务执行结束，失败与不利结果还需由derived/summary.json逐项审计。汇总程序在仓库根目录运行python summarize_supplement_v3.py。

与旧计时相比，本轮把M2和M3首次对象构造纳入计时，只能在本轮方法间作同期比较。新的随机样本、新区域和三层缓存组合不能替代严格几何证明或单一组件的因果识别。方法代码与补充设计由AI执行助手依据用户优化请求实现，具体原创边界在报告中说明。
