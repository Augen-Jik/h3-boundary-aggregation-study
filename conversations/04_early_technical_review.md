## 1\. 已有知识与可探索问题

H3 官方明确指出：层级关系具有严格的**逻辑包含性**，但只有近似的**几何包含性**。因此，细格的逻辑父格不一定等于点在粗分辨率下的直接编码结果。`cell_to_parent`、`latlng_to_cell` 均是现成 API。citeturn333933search4turn333933search2

`h3shape_to_cells_experimental(..., contain='full')` 也已存在，不能作为算法创新。citeturn333933search0turn333933search1

课程级探索可集中于：

- 不同分辨率差下，\(P(p)\ne D(p)\) 的比例及空间分布。
- 局部纠正能否减少误归属，同时降低重复批次的计算成本。
- 数据空间分布、缓存命中率如何影响收益。

## 2\. `full` 能否保证严格一致？

**不能仅凭该 API 推出全球严格一致。**

`full` 表示细格几何区域完全包含于指定多边形，不表示其逻辑父格必然与该多边形对应。

如果细格 \(f\) 完全位于粗格 \(c\) 内，那么在无数值边界歧义且几何语义一致的前提下，对 \(f\) 内点可推断 \(D(p)=c\)。

但还必须核实：

1. 该细格的逻辑父格是否为 \(c\)；
2. 是否覆盖全部可能输入，包括五边形、跨经线及极区；
3. 边界点、浮点误差、球面几何是否引入歧义；
4. 多边形生成和实验性 API 的版本稳定性。

建议构造安全映射：仅当 `full` 几何包含成立且 `cell_to_parent(f,rc)==c` 时，允许直接使用父格结果；其余点回退 `latlng_to_cell(p,rc)`。这仍是**待验证的充分条件**，不是全球正确性证明。

## 3\. 实验与强基线

| 数据 | 生成方式 | 主要检验 |
|--------|--------|--------|
| U：均匀 | 等面积球面采样，覆盖不同纬度 | 整体偏差与平均成本 |
| C：聚集 | 多中心空间簇，控制簇数量和离散度 | 缓存复用收益 |
| B：边界 | 沿粗格边界两侧按距离分层采样 | 纠正能力与极端误差 |

建议测试多组 \((rc,rf)\)，固定随机种子，并单独增加五边形、极区及跨日期变更线测试。

**强基线**应包括直接粗格编码 D、直接父格聚合 P、逐点双编码纠正，以及细格到粗格的精确缓存映射（首次遇到细格时直接粗编码并缓存）。最后一种尤其关键，可能比几何预处理更简单、更快。

时间测量必须分别报告：预处理、每点编码、几何判断、缓存查找、聚合及总耗时。

对同一空间分布，测试冷启动、首次批次及多个独立新批次；控制新细格比例和缓存命中率，绘制吞吐量及累计耗时曲线。禁止仅报告缓存预热后的加速比。

## 4\. 最可能的失败原因

1. **性能倒退：** H3 原生编码可能已经很快；Python 字典查找、几何判断及缓存维护反而增加开销。
2. **预处理膨胀：** 高分辨率差会扩大候选细格数量，增加内存和初始化成本。
3. **错误安全判定：** 将几何包含误认为逻辑父子关系，可能保留原有偏差。
4. **缓存收益被高估：** U 类数据细格复用率低，跨批次空间分布变化会降低命中率。
5. **实验结论失真：** 只测试规则六边形、忽略异常区域，或不同方法使用不同计时范围。

## 建议的最终研究主线

先用 D 建立逐点正确性基准，验证 P 的偏差；再比较局部纠正与精确缓存基线；最后给出**纠正率—预处理开销—批次复用率**三者的关系。

验收标准为：与 D 的逐点一致率、总耗时（含预处理）、峰值内存和跨批次盈亏平衡点。未覆盖全球边界语义前，只能报告测试范围内的一致性。
